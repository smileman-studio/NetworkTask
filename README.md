# NetworkTask
Реализация сервиса безопасного обмена сетевыми сообщениями между сервером и клиентом на базе плагина Mirror для Unity. Проект выполнен по [тестовому заданию](TaskDescription.md).

**Описание решения**

Архитектура построена с использованием DI-контейнера VContainer.
Для организации безопасного обмена сообщениями на клиенте создан сервис [INetworkService](Assets/NetworkTask/Scripts/Common/INetworkService.cs), который отвечает за обработку сетевых сообщений. Все остальные сервисы подписываются через него на нужные им типы сообщений. Для обработки сообщений на сервере создан сервис [ServerNetworkService](Assets/NetworkTask/Scripts/Common/ServerNetworkService.cs), который подписан на получение сервером служебных сообщений [SubscribeMessage](Assets/NetworkTask/Scripts/Common/SubscribeMessage.cs) и [UnsubscribeMessage](Assets/NetworkTask/Scripts/Common/UnsubscribeMessage.cs). Данный сервис регистрирует подписки от клиентов по ID типа сообщения и в дальнейшем отправляет сообщения только тем клиентам, которые подписаны на соответствующий тип.

Клиентская часть сетевого взаимодействия реализована двумя вариантами: BaseVersion и ClientPublishersVersion.

**BaseVersion**

Простая версия клиентского сервиса, которая по сути выступает оберткой над библитекой Mirror. Когда кто-то подписывается на сообщения, сервис пересылает делегат напрямую NetworkClient и отправляет сообщение на сервер о подписке. Решение прямое и рабочее для небольшог проекта, но имеющее несколько ограничений. Во-первых, в этой реализации каждый сторонний сервис должен сам следить за жизненным циклом соединения. Отправить подписку можно только когда клиент уже установил соединение с сервером. Т.е. помимо своих задач другие сервисы должны разбираться в логике сетевого соединения. Во-вторых, из-за особенностей реализации Mirror, у каждого типа сообщения может быть только один подписчик. Поэтому нельзя подписаться на одно сообщение в нескольких сервисах, вместо этого, если кому-то еще понадобится это сообщение, нужно создавать для этого типа новый сервис, который будет рассылать событие о получении сообщения, а остальные сервисы будут его слушать. Для маленького проекта это может быть не очень критично, но когда количество типов сообщений перевалит за 50 или 100 это станет неуправляемой мешаниной.

**ClientPublishersVersion**

Расширенная версия клиентского сервиса, которая имеет свою логику подписчиков и издателей. Вместо того, чтобы подписывать запросивший сервис напрямую в NetworkClient, сетевой сервис создает издателя [INetworkMessagePublisher](Assets/NetworkTask/Scripts/ClientPublishersVersion/INetworkMessagePublisher.cs) с данным типом сообщения в своей собственной коллекции. Запросивший подписку сервис слушает этого издателя, а издатель подписывается на сообщение в NetworkClient. Если кто-то еще захочет подписаться на это сообщение, то сетевой сервис подпишет его на своего издателя. Таким образом решается проблема множественных подписок. С использованим такой системы другим сервисам не нужно знать о состоянии соединения с сервером, они подписываются на сообщения сразу при инициализации. Серверный сервис же в свою очередь сохраняет подписки у себя и, если соединение еще не установлено, то отправит подписку на сервер после соединения. Так же во время переподключения к серверу произойдет обновление всех подписок в одном месте.

Для проверки каждого варианта настроены сцены BaseVersionScene и ClientPublishersScene.
После запуска нажать кнопку Host(Server + Client)
